# Registro de decisões técnicas — cupqy-web

| #   | Decisão                                                                                                                     | Motivo                                                                                                                                                                                                                                                                                                                 |
| --- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Vite 8 + React 19 + TypeScript 7** (template oficial atual)                                                               | Template padrão do Vite; o compilador nativo do TypeScript 7 deixa `tsc -b` muito mais rápido.                                                                                                                                                                                                                         |
| 2   | **oxlint** em vez de ESLint + typescript-eslint                                                                             | É o linter do template oficial; o `typescript-eslint` ainda não suporta TypeScript 7. Plugins habilitados: `react`, `jsx-a11y`, `typescript`, `import`, `vitest`, `unicorn`.                                                                                                                                           |
| 3   | **Tailwind CSS v4** com tokens em `@theme` e paleta padrão desativada                                                       | Reproduz a brand board com precisão e impede cores fora da identidade.                                                                                                                                                                                                                                                 |
| 4   | **Fontes auto-hospedadas** (Fontsource: Inter e Playfair Display variáveis)                                                 | Sem requisição a terceiros, melhor desempenho e funcionamento offline nos testes.                                                                                                                                                                                                                                      |
| 5   | **TanStack Query** para estado do servidor; **Context + reducer** para carrinho e sessão                                    | Evita dependências extras (Redux/Zustand) — o estado global do cliente é pequeno.                                                                                                                                                                                                                                      |
| 6   | **React Router 8** (modo data, `createBrowserRouter`) com rotas em português                                                | `FRONTEND_ORDER_PATH=/pedidos/:orderId` e `/redefinir-senha` já são usados pelo back-end.                                                                                                                                                                                                                              |
| 7   | **Tipos gerados do OpenAPI só para entradas** (corpos e query strings); respostas tipadas manualmente em `src/api/types.ts` | Os schemas de entrada do contrato vêm dos validators Zod (precisos). Os de resposta não marcam campos obrigatórios e omitem objetos aninhados (`payment`, `progress`, itens da cozinha); os tipos manuais seguem as _views_ do back-end. `npm run api:sync` atualiza o snapshot e `tsc` acusa divergências nos corpos. |
| 8   | **`openapi-typescript` executado via `npx`**                                                                                | A versão estável declara `typescript ^5` como peer; evita conflito com o TypeScript 7 do projeto.                                                                                                                                                                                                                      |
| 9   | Camada HTTP própria sobre `fetch` (sem Axios)                                                                               | Requisitos simples (JSON, token, timeout, retry de 401); menos dependências.                                                                                                                                                                                                                                           |
| 10  | **Supabase Realtime como gatilho** de invalidação + polling de segurança                                                    | Recomendação do back-end: os eventos só disparam um novo `GET` na API, que aplica as regras de apresentação. Se o Realtime não estiver configurado, o polling mantém a tela atualizada.                                                                                                                                |
| 11  | **Fluxo implícito** do Supabase Auth (padrão do `supabase-js` no navegador)                                                 | Os links de confirmação e recuperação funcionam mesmo se abertos em outro dispositivo/navegador (o PKCE exigiria o mesmo navegador).                                                                                                                                                                                   |
| 12  | Carrinho no `localStorage` com _snapshot_ para exibição; valores sempre confirmados por `POST /cart/validate`               | US08 RNF#01 (não perder o carrinho) sem confiar em preços locais.                                                                                                                                                                                                                                                      |
| 13  | Upload de imagem com `supabase.storage.uploadToSignedUrl` e progresso por etapas                                            | Segue o contrato do back-end (URL assinada). O SDK não expõe progresso de bytes; a UI mostra as etapas autorizar → enviar → confirmar.                                                                                                                                                                                 |
| 14  | `<dialog>` nativo para modais                                                                                               | Foco preso, `Esc` e camada superior nativos — acessível sem bibliotecas.                                                                                                                                                                                                                                               |
| 15  | E2E da CI com **rotas interceptadas** (API e Supabase Auth simulados)                                                       | Pipeline confiável e sem dependência de serviços externos; testes reais ficam em `e2e:hml`.                                                                                                                                                                                                                            |
